# Наш Host на durable-zero без изменения Zero

[Весь архитектурный пакет](../README.md) · [Текущая архитектура Host](../MAP.md)

Дата: 2026-11-02. Назначение по Diátaxis: объяснение рекомендуемого решения.

Этот каталог содержит исследование и архитектурное предложение. Переход не реализован. Внешняя композиция C остаётся вариантом для обсуждения, а не окончательно утверждённым планом миграции.

## Zero предоставляет регистрацию, но не весь lifecycle Host

Наши расширения можно вынести в отдельные пакеты без изменения исходников Zero. Версия `v0.7.0` предоставляет два способа подключения. Обычные Pi Extensions используют штатный интерфейс Pi. Вызов `openDurable({ builtins })` позволяет регистрировать native definitions, то есть определения задач, документов и инструментов Pi Durable.

Упаковка расширений не делает готовый `openDurable()` эквивалентом нашего полного Host. Нашему Host нужны управление запуском до `resume`, защищённая среда исполнения и авторизация перед commit. Для полного UI и reload также нужен доступ к extension runner. README Zero не определяет эти необходимые нам контракты.

Рекомендуемый вариант полного профиля использует внешний пакет интеграции. Пакет соединяет публичные компоненты Zero с существующей native-композицией нашего Host. Zero остаётся неизменённой зависимостью. Единственным движком выполнения остаётся Pi Durable.

Мы отвечаем за сборку компонентов и жизненный цикл runtime. Мы не копируем планировщик, транзакции или восстановление задач Zero.

Zero подходит как библиотечная основа. Однако исследование пока не подтверждает полноценность готового `DurableEngine/openDurable` как единственного способа запуска полного профиля. Если нужен именно готовый runtime Zero, исследованная версия не позволяет подтвердить сохранение всех текущих требований. Название «адаптер» не устраняет это ограничение.

## Границы поручения

Первым клиентом остаётся наш терминал. Архитектура предусматривает BB и iii, но их подключение в этой работе не выполняется.

Исследование не разрешает следующие действия:

- изменение Zero через patch, fork, monkey-patching, private imports или loader aliases;
- переход production, чтение рабочих БД или секретов, публикацию пакетов;
- запуск новых агентов или изменение текущей DeLM-доски.

Отдельный пакет не означает отдельный процесс. Он также не означает независимость от версии native SDK.

## Проверки не подтверждают полный переход

В исходном исследовании выполнен изолированный запуск штатных тестов `BuiltinExtensionRegistry`. Результат составил **3 PASS / 0 FAIL**. Тесты проверили регистрацию, отказ при повторном ID и обратный порядок teardown, то есть освобождения ресурсов. Исходники и поставляемый bundle показывают публичный экспорт точек интеграции.

Исследование не проверяло следующие свойства:

- полную цепочку установки и импорта зависимостей;
- запуск Host на Zero и восстановление наших native extensions;
- полный обмен запросом и ответом UI, подключение BB и iii;
- hot reload и совместимость рабочих данных.

Эти ограничения остаются открытыми. Редактура документа не добавляет проверок выполнения и не заменяет приёмку.
