## Дополнение: весь архитектурный пакет в одной папке

Поверх commit `830ad61af22b1585f1358896f286acd40492c7ca` публикуется **только документационное дополнение**:

- [MAP](MAP.md): точки входа, пути запросов, владельцы, незаконченные границы и таблица «где менять».
- [CHANGES](CHANGES.md): baseline Disler, наши изменения, настоящие dependency patches и пределы доказательств.
- [IMAGES-AND-HTTP](IMAGES-AND-HTTP.md): подтверждённый строковый input и Express, без выдуманного performance-вердикта.
- [zero/](zero/README.md): законченный пакет OBSERVE → THINK → ARCHITECTURE, матрица расширений, источники и узкие проверки. Это предложение внешней композиции, не изменение Zero и не выполненная миграция.

Перед подготовкой карты сравнены **665 опубликованных файлов `apps/` и `packages/`** с рабочей копией: расхождений и отсутствующих файлов не обнаружено. Нового захвата продуктового дерева не было. Общий Git index и исходники команды не редактировались.

Zero-пакет перенесён из локального `docs/host-design/durable-zero-packages-20261102/` в эту папку с исправленными относительными ссылками. Два небольших исследовательских лога сохранены как `.txt`; это отобранные результаты source/registry checks без production payload, а не выгрузка рабочих runtime-логов. Zero checkout, зависимости и приватные конфигурации не публикуются. Тестовый лог остаётся доказательством прежнего запуска, не новой приёмкой всего Host.

Read-only проверки пакета:

```sh
python3 docs/architecture/verify.py
python3 docs/architecture/zero/verify.py /path/to/clean/durable-zero-v0.7.0
```

Первый скрипт проверяет локальные ссылки, Markdown и перечисленные source-факты. Второй дополнительно сверяет чистый Zero checkout с pinned commit и проверяет публичные exports/lifecycle seams. Оба не запускают Host, модели или SQLite. Импорты полного npm-пакета, рендер схем и производительность здесь не проверяются.

Также не копировались Git-ignored `node_modules`, `dist`, базы SQLite, WAL/SHM, логи, приватные bindings и рабочие конфигурации. Исходная `.gitignore` сохранена. Для статической проверки в изолированной копии использовались ссылки на имеющиеся dependency trees; в Git они не входят.

Снимок не содержит установленные candidate archives и операторские `/tmp`-окружения. Локальные пути в исторических отчётах обозначают место получения доказательств, а не скачиваемый артефакт. Поэтому некоторые упоминания raw logs или delivery receipts намеренно не имеют публичной копии.

## Проверка публикации

Новые и изменённые текстовые файлы проверялись локальными шаблонами на private keys, provider/GitHub tokens, JWT, credential-bearing URLs, литералы credential-полей, приватные email и tailnet hostnames. Найденный операторский hostname скрыт; оставшиеся credential-like совпадения относятся к явным тестовым фикстурам и имени npm script `token`.

Это ограниченная проверка состава публикации, **не полный security audit и не доказательство отсутствия любого возможного секрета**. Production auth/config/DB для неё не читались. Результаты статических проверок кода — в [STATUS.md](STATUS.md); завершение commit/push не меняет их FAIL на PASS.

Документация проверяется на наличие относительных ссылок, структуру Markdown и пять Mermaid-блоков: четыре в обзоре и один в карте исходников. Визуальная браузерная приёмка Mermaid не заявляется. Для сравнения содержимого используйте SHA опубликованного Git-коммита, а не изменяющуюся рабочую копию.
