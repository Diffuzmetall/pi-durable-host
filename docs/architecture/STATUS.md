## Статические проверки снимка

Проверки выполнены **2 ноября 2026 года, около 19:27 UTC** в отдельной копии. Для каждого пакета выполнялась команда `node <typescript>/bin/tsc --noEmit -p .`. Проверки использовали TypeScript **5.9.3** и уже установленные деревья зависимостей. Backend и reload разрешают Durable **1.4.0**. Чистой установки зависимостей из сети не было.

Проверки выявили следующие несовпадения.

- В разрешённом Durable 1.4 отсутствуют `COMMIT_AUTHORIZATION_REVISION`, `ConversationIdle`, `Observation` и новый `beforeCommit`.
- Проверка терминала захватывает импортируемые backend-файлы и тесты. Среди ошибок есть отсутствующий `observeCommits`, новые usage-поля и несовпадение exports установленной сборки `@local/pi-durable-reload`.
- Эти результаты описывают несовпадения снимка и имеющегося дерева зависимостей. Они не доказывают, что замена версии исправит все 194 диагностики.

`git diff --cached --check` сообщил 22 предупреждения о пробелах в концах строк внутри трёх сохранённых `.patch`-файлов MCP. Их байты не изменялись. Эти файлы сохраняют материал исходного эксперимента, а не форматирование новой документации.

Проверка типов не запускает Host, модель или production-сессию. Публикация не включала полную сборку, runtime-тесты, чистую установку, новую независимую приёмку или проверку запущенных служб. Старый PASS не подтверждает результат для этого Git-коммита.

## Незакрытые условия завершения миграции

Снимок не подтверждает выполнение следующих условий.

1. Routes, streams и Store используют семантический контракт единственного владельца исполнения в реальном Host. Второй Harness и копия native state machine не создаются.
2. Один клиент работает с 1.4 и 1.5 через отдельные сборки и отдельные базы. Реальные запросы и ответы HTTP и SSE проверяют результаты, а не только импорты.
3. Сторонние компоненты и пакеты прошли полную приёмку. Наличие адаптации в experiments не подтверждает полного решения для GipPity 0.10.0 и удалённого `watchEvents`.
4. Закрыты исторические ограничения авторизации, изоляции и возврата release. Публикация кода не снимает их. Отчёты сохраняются в [restart repair](../host-design/verification/restart-repair-20261101/REPORT.md) и [hot-update](../host-design/verification/hot-update-20261101/REPORT.md).
5. Подготовлен воспроизводимый release без активации. Независимые проверки исходников и установленного кандидата относятся к одному digest, критерии DM1 закрыты.

**Нельзя запускать 1.4 на базе, которую изменила 1.5.** Восстановление старой резервной копии и возврат с сохранением новой истории дают разные гарантии. Совпадение SQL schema не доказывает безопасность возврата к старой версии.
