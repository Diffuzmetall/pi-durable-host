# Подключите BB к существующему Host

[Контракты и настройки адаптера](BB-ADAPTER.md)

Это инструкция для будущей интеграции. Полная интеграция с BB ещё не принята. Эта инструкция не подтверждает, что интеграция уже активирована.

**Без отдельного согласования не меняйте production, не выдавайте новые credentials и не перезапускайте Host.** Сначала проверьте подключение на изолированной сессии.

## Подготовьте совместимые компоненты

**Не используйте общий операторский токен вместо BB credential.** Не передавайте credential в аргументе команды или теле JSON-RPC. Полномочия определяет Host, а не данные модели или BB-запроса.

1. Выберите совместимые версии Host, SDK, адаптера и BB Core.
2. До первого изменяющего запроса проверьте доступные возможности через capability discovery.
3. Подготовьте серверный credential с нужным scope и существующую native цель. Не копируйте рабочую базу в BB.

## Зарегистрируйте провайдер

1. Зарегистрируйте `dpi-bb-provider` через существующий транспорт провайдера выбранного BB Core.
2. Передайте доверенную [конфигурацию запуска](BB-ADAPTER.md#доверенная-конфигурация-запуска) через среду процесса.

## Подключите точную native цель

1. Для первой привязки используйте `thread/start`. Для существующей привязки используйте `thread/resume`.
2. Проверьте, что resume не создаёт новую привязку без явного запроса.
3. Если выбранный Core требует подтверждения подготовленного Root, используйте реальный `thread/confirmRootAttachment`. Подтверждение должно относиться к точной цели.

## Проверьте интеграцию на изолированной сессии

1. Проверьте отправку и наблюдение.
2. Проверьте повтор запроса после потери ответа. Сохраните прежний Core request ID, не создавайте новый ID после таймаута.
3. Проверьте отключение клиента.
4. Отдельно проверьте управление children по критериям приёмки.

Сопоставьте результат с [контрактами и ограничениями адаптера](BB-ADAPTER.md). Компонентные тесты не заменяют полную приёмку BB.
