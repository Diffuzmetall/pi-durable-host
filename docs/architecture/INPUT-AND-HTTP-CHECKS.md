# Проверить будущий ввод изображений и замену HTTP-слоя

Это инструкция для будущей работы, а не отчёт о выполнении. Изменения, замеры и миграция в этой редакторской фазе не разрешены. [Объяснение ограничений](IMAGES-AND-HTTP.md) описывает существующий код.

## 1. Подготовить согласованный ввод изображений

1. Согласуйте typed input content в SDK и native boundary. Выберите текст, image blocks либо проверяемые attachment references. Формат ещё не принят.
2. Проверяйте MIME, размер, число вложений и полномочия на файлы на серверной границе. Не считайте произвольный серверный путь разрешением читать файл.
3. Включите неизменяемое содержимое или идентичность вложений в request fingerprint и восстановление journal. Один `requestId` не должен обозначать разные изображения.
4. Передавайте содержимое в native submit. Сохраните admission, receipt, reconcile и redaction.
5. Добавьте клиентское прикрепление изображений. Проверьте успешный ввод, отказ по лимитам или правам, повтор после потери ответа, несовместимый provider и восстановление клиента.

## 2. Сравнить HTTP-слои

1. Сравните Express, `node:http` и fetch-style router на одной сборке профиля.
2. Сохраните одинаковые данные, native-версию и нагрузку.
3. Измерьте cold start, idle RSS/heap, число открытых сессий и HTTP latency.
4. Измерьте SSE throughput/backpressure и восстановление после disconnect.
5. Выполняйте замеры в изолированной среде, а не на рабочем Host.

При замене сохраните auth/scope, body limits, wire errors, abort, SSE cleanup, idempotency и reconciliation. Проверьте, что отключение клиента не отменяет native работу, которую сервер уже принял.
