# Проверьте Pocket на изолированном стенде

[Выбор серверной части](PI-POCKET.md) · [Версии и интерфейсы](POCKET-REFERENCE.md)

Это план следующего минимального эксперимента, а не отчёт о выполненных действиях. В редакторской фазе стенд не запускался.

## Подготовьте стенд после разрешения

**Без отдельного разрешения не запускайте эксперимент.** Не открывайте существующие данные и не подключайте реальные credentials.

Физически исключите доступ стенда к рабочим базам и секретам, включая доступ родительского процесса и дочерних процессов. Одной замены `HOME` недостаточно.

1. Подготовьте изолированную копию Pocket 0.27.0, временный HOME и новую базу.
2. Настройте scripted model без реальных провайдеров.
3. Подготовьте HTTP-подключения двух клиентов, одного с поведением терминала, другого с поведением BB.

Реальные модели, подключения production-данных и миграция истории в эксперимент не входят.

## Проверьте сообщения, историю и восстановление

1. Заранее определите поведение при потере ответа на создание сессии. Создайте одну сессию.
2. Отправьте одну картинку. Проверьте `ImageContent` у модели и прочитайте изображение из истории.
3. Оборвите ответ submit. Повторите прежний ID и проверьте единственный submission и единственный эффект.
4. Повторите ID с другим payload. Проверьте явный конфликт.
5. Подключите оба клиента одновременно. Проверьте повторное подключение, историю, cancel и approval.
6. Остановите процесс во время незавершённого tool или task. Восстановите процесс и подтвердите отсутствие повторного внешнего эффекта.
7. Отзовите session access. Проверьте прекращение чтения и записи.

## Отдельно проверьте расширение MCP

1. Подключите native MCP drop-in к локальному безвредному MCP-серверу.
2. Проверьте reload и cleanup.
3. Только после этих проверок оцените перенос одного нашего расширения.
