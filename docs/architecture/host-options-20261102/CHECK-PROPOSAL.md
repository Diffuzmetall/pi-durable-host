# Предлагаемая проверка адаптера Ultimate или Recurse

Назначение по Diátaxis: инструкция для будущего изолированного эксперимента. Она выделена из [исследовательского отчёта](ULTIMATE-RECURSE.md). [Справочник](REFERENCE.md) содержит версии, интерфейсы и ограничения.

Эксперимент не выполнялся. Эта редактура не разрешает запуск runtime, моделей или серверов. Для выполнения необходимо отдельное разрешение.

## Условия до запуска

Физически исключите доступ стенда к рабочим базам и секретам, включая доступ родительского процесса и дочерних процессов. Одной замены `HOME` недостаточно. Используйте локальный тестовый provider, а не реальную модель.

Для Ultimate сначала обеспечьте серверную поддержку клиентского requestId. Для Recurse сначала определите допустимые учётные данные и маршрут BB и iii. Проверка операторского маршрута не подтверждает ограниченный service route.

## Порядок проверки

1. Подключите два клиента к одному владельцу выполнения. Проверьте серверную историю и повторное подключение SSE. Проверьте однократный допуск запроса на native уровне.
2. Оборвите ответ после commit. Повторите тот же ID с тем же payload. Затем повторите тот же ID с другим payload. После перезапуска проверьте receipt и отказ при конфликте.
3. Повторите interrupt-запрос. Проверьте, что повтор не отменяет уже начатый новый run.
4. Передайте малое PNG. Затем передайте изображение с повреждением и изображение с превышением лимита. Сверьте сохранённые blocks с запросом тестового provider.
5. Зарегистрируйте минимальные native task/doc и lifecycle probe. Проверьте bind до resume и reload. Завершите одну сессию. Проверьте, что другая сессия не повреждена.

Проверки относятся к одному серверному владельцу и его реальному протоколу. Они не подтверждают перенос истории или активных задач между приложениями.
