# Задание: установить Pi Durable Host в изоляции

Установи host из `https://github.com/Diffuzmetall/pi-durable-host` в новом локальном каталоге. Цель — воспроизводимый запуск с faux provider и реальный native ответ через публичный SDK, без живых моделей.

## Входные параметры

- Каталог checkout и отдельные пустые install/data/work directories.
- Допустимый loopback port.
- Разрешены локальная установка dependencies и сборка; иные расходы/действия не подразумеваются.

## Источники

Прочитай README, docs/STATUS.md, docs/GETTING_STARTED.md и manifests затрагиваемых пакетов. Подтверди требуемый Node и реальные команды, не копируй устаревший CLI наугад.

## Готово, когда

- Backend/SDK собраны в tarball и установлены отдельно от checkout.
- Новый host использует только disposable HOME/dataDir/workspace и faux provider.
- SDK прошёл protocol discovery, создал session и получил настоящий native assistant result/receipt.
- Повтор неизменённого intent не создаёт новую работу; чужой credential не получает доступ.
- Процессы проверки остановлены; полезные логи и пути к артефактам сохранены без секретов.

## Ограничения

Не открывай реальные session databases, не меняй глобальные Pi/auth/MCP settings, не ставь пакеты глобально, не отключай guards. Не вызывай живые/платные модели и не отправляй приватный код внешним провайдерам. Не печатай токены: создай локальный fixture credential и передавай его только через приватное окружение/файл. Не коммить, не публикуй и не deploy без отдельного запроса.

Если локальный port или требуемый инструмент недоступен, выбери безопасный локальный вариант либо сообщи конкретный blocker. Не объявляй установку полной по одному успешному npm install.

## Отчёт

Укажи commit, версии, проверенные команды/exit codes, пути к tarball и точные результаты. Отдельно перечисли непроверенное и любые внешние зависимости. Не показывай значение credential.
